# Onda 7 Implementation Plan — Convênios/TUSS, Conexão WhatsApp por QR e Fechamento de Pendências

> **Para agentes agentic:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`
> (recomendado) ou `superpowers:executing-plans` para executar este plano tarefa por tarefa.
> Passos usam sintaxe de checkbox (`- [ ]`) para rastreamento.

**Goal:** Modelar convênio como entidade com preço por exame e código TUSS/AMB, permitir que
cada laboratório conecte o próprio WhatsApp por QR code (sem API oficial da Meta, via gateway
Evolution API), e fechar as 7 pendências mecânicas herdadas das ondas anteriores.

**Architecture:** Três tabelas novas (`insurances`, `exam_prices`, `exam_synonyms`) com RLS
fail-closed; `exam_catalog`/`proposals`/`proposal_items` ganham colunas; um gateway
self-hosted (Evolution API) roda ao lado do backend no `docker-compose`, falando REST +
webhook com um driver novo (`EvolutionWhatsAppDriver`) que se pluga no `WhatsAppService`
existente sem tocar no caminho de mensagens já construído (`findOrCreateByPhone` →
`createFromPatient`). Tudo entra pelos pontos de extensão já documentados:
`ApiModuleFactory` (backend) e `route-config.ts`/`routes/index.tsx` (frontend).

**Tech Stack:** Express 4 + TypeScript ESM · PostgreSQL 16 (RLS) via PGlite nos testes ·
React 18 + Vite + TanStack Query + Zustand + Tailwind (tokens CSS) · Playwright (E2E) ·
Evolution API (Docker, self-hosted) como gateway WhatsApp.

**Spec:** `docs/superpowers/specs/2026-08-30-onda-7-design.md` — este plano implementa
integralmente os Blocos A, B e C de lá. Leia o spec inteiro antes de começar qualquer tarefa;
os Apêndices A/B/C contêm os dados exatos do seed (convênios, códigos TUSS, sinônimos).

## Global Constraints

- **Regra Zero:** nada de endpoint/tabela/componente/token fora de `docs/` — Fase 0 documenta
  antes de qualquer implementação.
- **Multitenant sem exceção:** toda query filtra `tenant_id`; tabela nova entra com RLS
  **na mesma migração** que a cria (senão não trava, vaza).
- **Total calculado no backend:** `totalPrice`/preço de item nunca vem do cliente.
- **Alçada de desconto:** validada sempre no backend.
- **Estágios:** só `ALLOWED_TRANSITIONS`; `perdido` exige `reasonLost`.
- **Design:** zero hex/raio-px/nome-de-fonte/espaçamento cru em componente — só tokens CSS
  (`no-hardcoded-tokens.spec.ts` varre `src/components/` e `src/pages/`).
- **TypeScript:** `strict: true`, `any` proibido — `unknown` + narrowing.
- **Auditoria:** ações críticas (convênio, preço, conexão de canal, aceite de termo) geram
  audit log.
- **Erros:** `BusinessError` tipada → formato de `docs/api/API_ERRORS.md`; recurso de outro
  tenant → `NOT_FOUND`, nunca `FORBIDDEN`.
- **Dinheiro/data:** número decimal no fio, nunca string formatada; datas ISO 8601 UTC.
- **Sem `console.log`** no backend — logger. Sem segredo hardcoded — env var.
- **ESM:** import relativo no backend leva `.js`; frontend usa alias `@/`.
- **Envelope de resposta (D-070):** listagem = chave nomeada + `pagination`; recurso único
  (GET/POST/PATCH) = objeto cru; composto = uma chave por parte; sem corpo = `204`.
- **Isolamento de plataforma:** todo router de dado de laboratório usa `denyPlatformOperator()`
  e entra em `backend/tests/kernel/route-tenant-isolation.spec.ts` (meta-teste reprova rota
  nova sem declaração).
- **`page` sempre com teto:** `MAX_PAGE = 10_000` em todo service novo (padrão de
  `patient.service.ts`/`proposal.service.ts`).
- **Teste que passa com a implementação desligada não é teste:** prove o comportamento, não a
  ausência dele.

CREATE TABLE insurances (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID NOT NULL,
  name VARCHAR(255) NOT NULL,
  official_name VARCHAR(255),
  ans_code VARCHAR(20),
  type VARCHAR(30) NOT NULL,
  is_active BOOLEAN NOT NULL DEFAULT TRUE,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW(),
  FOREIGN KEY (tenant_id) REFERENCES tenants(id) ON DELETE CASCADE,
  UNIQUE (tenant_id, name),
  CHECK (type IN ('cooperativa','medicina_grupo','seguradora','autogestao','especial'))
);

CREATE INDEX idx_insurances_tenant_id ON insurances(tenant_id);
CREATE INDEX idx_insurances_active ON insurances(tenant_id, is_active);

CREATE TRIGGER trg_insurances_updated_at

CREATE TABLE exam_prices (

  tenant_id UUID NOT NULL,
  exam_id UUID NOT NULL,
